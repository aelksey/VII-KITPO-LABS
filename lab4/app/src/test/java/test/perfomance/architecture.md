# Архитектурное описание пакета `test.performance`

**Назначение пакета:** Автоматизированное нагрузочное тестирование алгоритмов сортировки (`QuickSortStrategy`, `MergeSortStrategy`) структуры данных `CustomList`, экспериментальное определение вычислительной сложности по времени (процессорный ресурс) и по памяти (динамическая куча JVM).

### Архитектурные принципы и методы замеров
В основе архитектуры профилирования лежат три ключевых компонента:

* **Изоляция состояния памяти (Memory Cleanliness Strategy):** 
  Перед фиксацией базового уровня потребления кучи (Heap) для каждой новой размерности принудительно вызывается системный сборщик мусора (`System.gc()`), финализируются неиспользуемые объекты (`Runtime.getRuntime().runFinalization()`) и устанавливается аппаратная задержка в `150 мс`. Это минимизирует влияние фоновой активности JVM на результаты измерений.
* **Измерение «грязного» времени (Wall-Clock Time):**
  Замер интервала работы алгоритма сортировки производится с помощью высокоточного системного таймера процессора (`System.nanoTime()`), фиксирующего общее время выполнения потока, включая накладные расходы внутри структуры. Измеренная дельта наносекунд переводится в миллисекунды.
* **Динамическая верификация теоретической сложности:**
  Внутри пакета реализован автоматический расчет математических коэффициентов роста ресурсов для оценки вида функциональной зависимости:
  * **Временной коэффициент (\(K_{time}\)):** Расчет отношения реального времени к теоретической функции роста: \(K_{time} = \frac{T}{N \cdot \log_2 N}\). Стабильность этого коэффициента при увеличении масштаба N доказывает сложность алгоритма \(O(N \log N)\).
  * **Пространственный коэффициент (\(K_{mem}\)):** Расчет плотности выделения памяти на один элемент структуры: \(K_{mem} = \frac{\text{Memory}}{N}\). Постоянство коэффициента доказывает строго линейный характер зависимости O(N) за счет блочного выделения массивов в `CustomList`.

### Структура и компоненты пакета
Пакет состоит из двух ключевых модулей:
1. **`SortingPerformanceTest.java`** — управляющий тест-класс JUnit 5. Отвечает за инициализацию структуры данных с заданной вместимостью блоков, наполнение её псевдослучайными числами (для исключения деградации быстрой сортировки на упорядоченных массивах) и управление жизненным циклом замеров на сетке размерностей (N = 100, 1000, 5000, 10000).
2. **`PerformanceReportLogger.java`** — подсистема форматирования и логирования. Производит математическую калькуляцию коэффициентов и осуществляет вывод структурированной таблицы результатов на английском языке в консоль сборщика Gradle. Для предотвращения сбоев отображения (кракозябр) в терминалах операционных систем Windows (в условиях несовпадения кодировок UTF-8 и CP1251) в логгер встроен компонент фильтрации и автоматического маппинга названий стратегий на латиницу (`sanitizeStrategyName`).
